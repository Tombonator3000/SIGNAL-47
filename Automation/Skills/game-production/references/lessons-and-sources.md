# Origins and limits

Created 12 September 2026 from the user's SIGNAL / 47 collaboration and the linked PaperRoute account. This is a synthesis of transferable decisions, not a copy of another project's code or a universal technology prescription.

## PaperRoute: author-reported production experience

Source: [Emm Tee / builtbysketch, 12 September 2026](https://x.com/builtbysketch/status/2098773631249854478), read in full through the browser during this conversation.

The account emphasizes separate behavior/art iteration, scripted Blender assets, selective generated character meshes and pose/render review before integration. Its workload, token totals, speed and device results are the author's reports, not independently reproduced here. Reuse the production pattern; do not promise its schedule, choose a model from it or import its unverified performance assumptions. This skill includes no source article text, proprietary assets or copied implementation.

## SIGNAL / 47: concrete project evidence

Public records for the examples, not dependencies required to use this skill:

- [DesignBible13](https://github.com/Tombonator3000/SIGNAL-47/tree/main/Docs/DesignBible13): complete proposed story, explicit content ceiling, maps, UI states and estimated pacing. A design package is not implemented gameplay or measured duration.
- [Menu14](https://github.com/Tombonator3000/SIGNAL-47/tree/main/Docs/Menu14): new-shift confirmation and preservation of previous checkpoint files. The paper puzzle review also exposed an accidental early disclosure in a clue.
- [Recovery15](https://github.com/Tombonator3000/SIGNAL-47/tree/main/Docs/Recovery15): reviewed previous-case selection, backup handling, controlled write failures, scene restoration and unchanged original media. Fifty API-driven checks passed in the player and extracted package at the recorded revision; real input/performance gates remained open.
- [NightSky12](https://github.com/Tombonator3000/SIGNAL-47/blob/main/Docs/NIGHT_SKY_12.md): an inspected visual candidate with source provenance, without transferring older performance measurements to a changed sky.

The Recovery15 packaging session initially used an overly strict mode-equality check. A failed prerequisite was followed by an unintended direct-player fallback. The corrected delivery run explicitly resolved the extracted launcher and checked content identity and runtime permissions separately. This motivates fail-closed delivery scripts; the intermediate run was not package evidence.

Portable lessons: canonical source differs from mirrored references; generated images differ from runtime evidence; old fixtures must be isolated and preserved; a merged candidate can remain unverified; reversible and authorized work can continue while one required test environment is unavailable.

Project-specific facts that must not become defaults: Unity/Blender versions, absolute paths, SARO lore/constants, 5–6-hour duration, three locations, test counts, a locked Kubuntu desktop, repository visibility, existing spending allowance or merge permission. Resolve these from each new project. Other tools and models can fill the same production roles when actually available and suitable.
